# 微信 LSPosed 模块 + DSH Go 插件

> 版本：1.0.1 ｜ 目标：微信 8.0.76（arm64，真机 Root + LSPosed）
> 状态：**收发链路已跑通**，日常可用（私聊已验证；群聊需 @，未做端到端验证）

## 这是什么

让手机上的**个人微信**由 DSH 里的大模型代答，语气像真人：

```
别人发微信
  → LSPosed 模块在微信进程里读到消息（数据库层）
  → HTTP POST 到 DSH Go 插件的本地端口
  → 插件拼人设 + 记忆 + 最近对话，调云端模型
  → 切句、算延迟，返回 reply.out
  → 模块用微信自己的发送流程发出去
```

DSH 只管**思考**（人设、记忆、模型、切句、节奏）；模块只管**通道**（读消息、发消息）。

## 三个组成部分

| 组件 | 位置 | 作用 |
|---|---|---|
| LSPosed 模块 | `lsposed-module/` | Hook 微信，收发消息 |
| DSH Go 插件 | `dsh-plugin/` | 桥接服务 + 面板 |
| 数据/人设 | 插件 `data/` 目录（运行时生成） | 配置、白名单、记忆、人设 |

## 五分钟装好

1. 编译并安装模块：`cd lsposed-module && bash tools/build-apk.sh`
2. LSPosed 里启用模块，作用域勾选 **微信**
3. 强制停止微信后重新打开（主进程才会注入）
4. 装插件：`dsh plugin --profile web add ./dsh-plugin`，引擎启动后监听 `127.0.0.1:18765`
5. 面板「全部功能 → 微信参数」：把要回的人加进白名单
6. 让对方发一条消息，验证能回

## 已知限制

- **只回文本**：表情包、图片、语音进来会变成 `[表情]`/`[图片]`/`[语音]` 占位文字，bot 不会发真表情包
- **群聊未验证**：代码支持，但白名单和 @ 规则没做过端到端测试
- **断线不补**：引擎重启期间收到的消息直接丢弃，不排队
- 微信升级会改混淆名，需要重新定位发送入口（见 04）
