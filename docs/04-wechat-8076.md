# 微信 8.0.76 实测锚点

目标：`com.tencent.mm` 8.0.76，19 个 dex，`base.apk` 约 266 MB。

## 混淆事实

- `com.tencent.mm.storage` 下的类全部短名，**不存在 `MsgInfo` 这个类**（旧方案里的 `storage.MsgInfo` 是错的）
- 消息实体是 `y11.r1`，其工厂入口是 `y11.s1`
- 消息类型枚举在 `e01.e2`（`e2.C(talker)` 返回私聊/群的文本类型）
- `com.tencent.wcdb.*`（腾讯自研 SDK）**不混淆**，这是收消息的稳定锚点

## 收消息

Hook `com.tencent.wcdb.database.SQLiteDatabase` 的 `insert` / `insertWithOnConflict` / `insertOrThrow` / `replace` / `replaceOrThrow`，看 `args[0]=="message"` 的 `ContentValues`。

过滤：

- `isSend == 0`（只处理别人发来的）
- `talker` 不以 `gh_` 开头、不是 `filehelper`
- 群聊要求 `content` 含 `@`
- 按 `talker|content|createTime` 做 10 秒去重（同一条会被多个 insert 方法重复触发）
- 非文本类型（3/34/42/43/47/48/49）转占位文字，见 02

拿到的字段：`talker`、`content`、`isSend`、`type`、`createTime`。

## 后台延迟（重要）

微信被系统「缓存应用冻结」后，消息能弹通知，但**消息表要等主进程解冻才写**，收消息 Hook 会晚几十秒到两分钟。日志里 `比发送时间晚 Ns` 就是这个差值。

解法：在主进程里播放一条 8kHz、音量为 0 的静音音频流（`KeepAlive`）。Android 把「正在播放音频」的进程当可感知进程，不进冷宫。

- 代价：几乎为零，不出声
- 效果：后台/清后台后延迟稳定在 0–5 秒
- 不解决：微信进程被系统直接杀死（那时会走重新拉起，仍有一段延迟）

试过但走不通的：Hook `NotificationManager.notify` 抓通知内容 —— 微信不走这个入口，一条都抓不到。

## 发消息（唯一可用配方）

```java
Object msg = XposedHelpers.callStaticMethod(s1, "a", talker);   // y11.s1，工厂
setIntField(msg, "e", e01.e2.C(talker));  // 消息类型：私聊/群 的文本类型（1）
setIntField(msg, "f", 0);
setIntField(msg, "i", 5);
callMethod(msg, "e", text);               // 正文
callMethod(msg, "g", talker);             // talker
Object n1 = callMethod(msg, "a");         // 交给发送器
callMethod(n1, "a");                      // 入队
```

三个必须点：

1. **ClassLoader 必须是微信的**（`lpparam.classLoader`），模块自己的 loader 找不到 `y11.s1`
2. 类型字段 `e` 必须用 `e01.e2.C(talker)` 的结果；写死 0 会入库成 `isSend=1 type=0`，消息不可见
3. `i=5` 是发送场景，缺了不生效

## 已排除的路径（不要再用）

| 尝试 | 结果 |
|---|---|
| 构造 `uk` 克隆对象调 `run` | `mChattingContext`（`tk.d`）为 null 时直接返回，静默无效 |
| Hook `kl5.s5` / `tk#o0` | 文本发送根本不经过，hook 不触发 |
| 直接写数据库 | 消息不入发送队列，对方收不到 |

## 版本升级后要重找的符号

| 用途 | 8.0.76 | 找法 |
|---|---|---|
| 消息工厂 | `y11.s1#a(String)` | 搜 `message` 表写入附近调用链 |
| 消息实体 | `y11.r1` | 工厂返回类型 |
| 类型枚举 | `e01.e2#C(String)` | 搜 `isSend` 写入处 |
| 收消息 | WCDB（大概率不用改） | `com.tencent.wcdb.database.SQLiteDatabase` |

## 构建 APK（无 Android Studio）

```bash
cd /root/workspace/wechat-lsposed-module
bash tools/build-apk.sh
# 产物 build/manual/wechat-bridge-<VERSION>.apk，并复制到 /sdcard/Download/DSHGO/
```

工具链：`javac`（JDK 17）→ `d8`（r8.jar）→ `aapt package` → `zipalign` → `apksigner`（`build/debug.keystore`）。
版本号来自仓库里的 `VERSION` / `VERSION_CODE` 两个文件，构建时注入 `BuildConfig` 和 aapt。

## 验证注入是否成功

模块启动会往 `/api/log` 推一行 `WeChatBridge <版本> 启动`，带进程名前缀：

- 只有 `:appbrand0` / `:push` → 主进程没注入，强制停止微信再打开
- 有 `com.tencent.mm | WeChatBridge ... 启动` → 正常

日志落在插件 `data/bridge.log`，或在面板看今日消息数是否增长。
